## Blockers / Notes

### Apprentissages techniques

#### Embroider auto-discovery sur `src/schemas/*.ts`
Tout fichier sous `src/schemas/` est automatiquement intégré dans `app-js` du `package.json` par le linter rollup pretest hook. Cela exige un `export default` pour chaque fichier, même si le module n'a que des types. **Workaround** : exporter un stub `const SchemaName = { type: 'xxx' }; export default SchemaName;` pour les schemas types-only (cas de `sprints.ts` en P7 — pas de schema WarpDrive enregistré).

À considérer en refactor P11/P12 : déplacer les types-only schemas hors de `src/schemas/` (ex. dans `src/types/`).

#### Drag-drop natif HTML5 dans jsdom/vitest-browser
`DataTransfer` n'est pas correctement polyfillé. Les tests intégration ne peuvent pas simuler un vrai drag-drop. Validation : screenshot manuel + dispatch d'`DragEvent` programmatique (cf. `p7-kanban-drag-drop.png`). E2E réel via Playwright en P13.

#### Filtre `Mes tâches` proxy temporaire
`task.createdById === currentUser.id` est un proxy pour les vrais assignees. Les vrais assignees nécessitent `tasks.loadAssignees(taskId)` async → trop lourd pour un filtre côté client. Reporté en P12.

#### Optimistic update + rollback
Pattern utilisé : mutation directe `task.status = newStatus` (le `@tracked` du WarpDrive record déclenche le re-render). En cas d'erreur PATCH, restore le `previousStatus` + alerte temporaire 4s. Marche bien en `MSW`-mocked. À tester en E2E P13 avec un vrai backend.
